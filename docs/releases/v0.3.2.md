**Find, steady captures: preview release.** A maintenance release: the device tools no longer
fail now and then while capturing the screen, and every release is recorded. The app and the
pack are those of 0.3.1 apart from the version; the pack format stays 1.

### What is new

- Device tools: the RPC session waits for the echo of `start_rpc_session` instead of any
  newline. A CLI prompt arriving late left the echo in the RPC buffer, and a capture failed
  now and then with "unsupported wire type 4"; 12 of 12 captures and a walk passed on the
  device with the fix.
- Every published release has a Majordomus record (`.ai/repo/releases`), written by
  `just release-record <tag>` from the release GitHub serves, each digest checked against its
  `SHA256SUMS`.

Hardware evidence: device and simulator frames compared on official 1.5.1 with a local build of
the tagged source (24 of 24); the manifest names the FAP's and the pack's SHA-256. The README's
device gallery was recaptured with the same build.

Each FAP ships with a `.build.json` (SDK URL and SHA-256, API, source commit); the pack ships
with its build report. Everything is listed in `SHA256SUMS`, and CI re-downloads the published
files and checks them against it.

### Install

1. Download the FAP whose API matches your firmware and `kompendium-0.3.2.pkp`; verify both
   against `SHA256SUMS`.
2. Copy the FAP to `SD/apps/Tools/` and the pack to `SD/apps_data/prismatic/` (or, from a
   checkout, `just bridge push-pack <pack>`). A 0.3.1 install already has these pages; the
   pack bytes are the same.
3. Open **Apps → Tools → Prismatic**.
